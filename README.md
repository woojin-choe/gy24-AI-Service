## 이거부터 보셈

1. [Git·GitHub 사용 가이드](docs/git-guide.md)를 따라 저장소를 내 컴퓨터에 받습니다.
2. 아래 대회 일정과 대회별 아이디어를 읽습니다.
3. 작업 전에 최신 내용을 받고 개인 브랜치를 만듭니다.
4. 수정한 내용을 커밋하고 업로드한 뒤 PR로 팀원에게 검토를 요청합니다.

## 자주 쓰는 명령어

**받을 때:** `git pull`은 현재 브랜치의 최신 내용을 받습니다. 팀의 통합 내용은 `main`에서 받습니다. 커밋하지 않은 변경이 있으면 먼저 [임시 보관 방법](docs/git-guide.md)을 확인하세요.

```bash
git switch main
git pull
```

**올릴 때:** 내 작업 브랜치에서 아래 세 줄을 실행합니다. 메시지는 `docs: 고용24 기획안 수정`처럼 바꾼 내용을 적습니다.

```bash
git add .
git commit -m "메시지"
git push
```

새 브랜치의 첫 업로드만 `git push -u origin 내-브랜치-이름`을 사용합니다. 업로드 후 PR을 만들어야 `main`에 합칠 수 있습니다. `git add .` 전에 `git status`, 커밋 전에 `git diff --staged`로 올라갈 파일을 확인하세요.

## 우리 팀 협업 약속

- `main`은 검토한 내용을 모으는 브랜치입니다. 개인 브랜치에서 작업하고 PR로 합칩니다.
- 한 브랜치·한 PR에서는 한 가지 작업을 다룹니다. 같은 파일을 수정할 때는 팀원과 먼저 조율합니다.
- 커밋 메시지는 `종류: 변경 내용`으로 씁니다. [커밋 규칙과 예시](docs/git-guide.md#커밋-메시지-규칙)를 참고하세요.
- PR에 변경 이유·내용·확인 방법을 적고, 다른 팀원 최소 1명의 리뷰를 받은 뒤 합칩니다. 이 규칙은 팀 약속이며 자동 강제하려면 관리자가 GitHub 브랜치 보호를 설정해야 합니다.
- API 키, 비밀번호, `.env`, 개인 정보는 올리지 않습니다. 조사 자료에는 출처와 확인 날짜를 적습니다.
